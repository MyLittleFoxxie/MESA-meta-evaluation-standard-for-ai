# Terminology comparison

The OECD terms below are from Chapter 6, printed pp. 101–102 (PDF pp. 103–104). Its three groups are **Validity, Consistency and Fairness**. They are a way to characterise evaluation instruments, not three scores. Some facet values are preferred in context; others describe differences without ordering them.

This is a conceptual correspondence for future consideration. It does not claim that the current MESA questions were historically derived from OECD or that the sources use identical meanings.

| OECD group and facet | Meaning in Chapter 6 | Related review activity and boundary |
|---|---|---|
| Validity — Capability | Whether an instrument measures task performance or supports a capability interpretation. | Connect the intended phenomenon to tasks and claims (S01, ECBD). A task score does not establish a broad capability. |
| Validity — Coverage | Representativeness of what is sampled. | Examine the task space and excluded cases. This is not the number of review questions answered. |
| Validity — Purpose | Research, conformity or another use. | Identify intended use before judging suitability. Research usefulness and certification are different claims. |
| Validity — Realism | Toy, gamified, realistic or real life evaluation. | Examine transfer to use conditions. A realistic simulation is still not observed deployment. |
| Validity — Reference | Absolute results or results relative to a reference. | Explain scale, criterion and comparison population. A human baseline requires specified conditions. |
| Validity — Specificity | Whether other abilities or tasks interfere with the intended measurement. | Examine alternative explanations. OECD’s “contaminated” here does **not** specifically mean training data leakage. |
| Consistency — Adjustability | Unstructured, ablatable or adaptive use of instance characteristics. | Examine subgroup/difficulty analysis and selection of items. It is not the reviewer’s ability to edit a form. |
| Consistency — Containedness | Dependence on external conditions during testing. | Document tools, people, services and environment. External interaction is not automatically a defect. |
| Consistency — Judgeability | Manual, automated or mixed scoring. | Identify who or what assigns scores, with what rules. It does not mean how easy the benchmark is to review. |
| Consistency — Reliability | Low variance for the same subject on repetition, given testing conditions. | Seek repeated measurement evidence. This differs from sources using reliability to mean few model errors or prompt robustness. |
| Consistency — Reproducibility | Whether the same test interactions can be generated again, including stochastic cases. | Record materials, implementation and randomness. Exact reproduction does not establish construct validity. |
| Consistency — Variation | Fixed, altered or procedurally created instances. | Describe changes to test inputs. Variation does not itself show representativeness or resistance to leakage. |
| Fairness — Ambition | Short or long term aims when the instrument was created. | Describe intended horizon. It is not a measure of social fairness or benchmark quality by itself. |
| Fairness — Antecedents | Created for AI or adapted from human tests. | Examine assumptions introduced by transfer. A human test’s validity evidence does not transfer automatically to AI. |
| Fairness — Autonomy | Autonomous system, coupled system or component. | Specify the system being evaluated, including human or tool support. |
| Fairness — Objectivity | Loose, customised or independent specification across test takers. | Check comparable evaluation conditions. It is not a guarantee of unbiased interpretation. |
| Fairness — Partiality | Favouring technologies, conditions or cultures irrelevant to the intended result. | Examine irrelevant advantages. Keep this separate from fairness of a model’s downstream decisions. |
| Fairness — Progression | Static capability or its development during the test. | Distinguish an achieved score from learning within the evaluation. It is not benchmark maintenance over calendar time. |

## Terms that should remain distinct

| Term | Difference to preserve |
|---|---|
| Validity | The Standards concern evidence supporting score interpretations and uses. OECD groups classification facets under this heading. Individual papers sometimes use narrower definitions. State the intended meaning. |
| Consistency | OECD’s umbrella includes scoring, repetition, reproduction and test variation. It is broader than reliability alone. Do not replace all uses of reliability with consistency. |
| Fairness | Test taker fairness, equal evaluation conditions, demographic disparities and reviewer access have different objects. Name the object and evidence. |
| Accessibility | Distinguish access to data/code, ability to run an evaluation, access for people with disabilities, readability, understanding and effort. This review focuses on the latter review activities but does not equate them. |
| Usability | BetterBench considers benchmark implementation and documentation; BenchScout studies a search interface; MESA’s intended concern is use of a review procedure. These outcomes are related but not interchangeable. |
| Not sure / N/A | OECD sometimes uses N/A where methodology is unclear. EFPA has item dependent missingness anchors. MESA’s current choices must be explained on their own terms. Do not mechanically recode other instruments. |
| Checking / outcome | Reporting a contamination check, a reliability analysis or a bias analysis establishes that a procedure was described. It does not establish a favourable result. |
| Description / judgment | Identifying the stated purpose or metric differs from judging whether that information is documented adequately, and both differ from validating the underlying claim. |

An OECD aligned vocabulary can improve consistency of exposition, but a renaming exercise would not demonstrate accessibility. Retain the source terms where they matter and explain correspondences in plain language. No MESA question or domain was renamed in this phase.
