# Protocol 3 — preparation draft

Status: not frozen. Replaces the prospective execution design in protocol 2.1; it does not replace its historical calculations. The prior manifest and every referenced file are preserved under `../../history/protocol-v2.1/` with original relative paths.

## Question and outcomes

Across selected configuration and repository cases, do review findings change source requirement verdicts in ways supported by separate target observations, compared with task matching alone?

Keep two configurations, threshold 0.70, 95% Wilson intervals, and separate primary and stability repetitions. Source tasks are observations within cases, not independent requirement decisions. Repetition 1 supplies primary outcomes; repetition 2 assesses stability and is never pooled. M1 uses aggregate source observations. M2 uses the matched subset. M3 uses exactly M2's observations and bounds and adds the five required review judgments. Missing evidence and defects both prevent support but remain different evidence states. Do not remove tasks after reviewing outcomes to improve M3.

Target intervals yield Supported when LB >= 0.70, Contradicted when UB < 0.70, and Unresolved otherwise, including no observations. Report the source/target verdict table and denominators, including unresolved target evidence. Discrepancy is not proven population error. Equal coverage controls are secondary descriptive comparisons. No organizational utility or human decision benefit is estimated.

## Selection

Retain SymPy; screen Django and Sphinx to replace Requests and Flask. The pinned inventory has 75, 231, and 44 candidates respectively. These counts do not imply eligibility or a planned run budget. Do not substitute repositories if feasibility fails. Record the blocker. Sample counts remain unfrozen until eligibility, precision, and cost review.

For each candidate obtain a repository commit, issue text, environment specification, target test identifiers, evaluation command, reference fix and its hash. Check the intended baseline failure and reference success in separate clean workspaces. Missing tests, unrelated failures, or setup errors do not establish eligibility. Selection must not use model performance. Preserve every rejection and reason.

Target selection requires a documented check against source and pilot issue identities, shared patches, and related issues. Empty automated overlap results do not discharge the manual related issue check. Do not claim unseen training data merely because source and target task identifiers differ.

## Reviews

Record each of C05, C07, C12, C14, and C28 with evidence location, scope (release, configuration, task, subset), judgment, rationale, detection limits, audit execution, method adequacy, empirical finding, warrant, author and assistant roles, and affected cases. Missing evidence is not a defect. Verified means warranted within the documented detection limits, not proof of absence. Preserve review versions and freeze the policy and judgments before target outcomes. Uniform abstention is a reportable outcome, never a reason to weaken the policy.

## Execution and failure policy

Provider execution is disabled in this preparation release. Existing fixture pilots do not establish repository or adapter feasibility. An adapter must demonstrate observed model identity, step enforcement (30), timeout enforcement (900 seconds), usage logging, and a filesystem access boundary excluding reference fixes and hidden evaluation artifacts. Separate folders are insufficient. Missing capabilities block execution; never infer model identity from a display name.

A later pilot uses two eligible tasks per repository and both configurations. Pilot tasks are excluded from main samples. Run limits exhausted during an otherwise functioning agent attempt are budget outcomes, not infrastructure exclusions. Preserve infrastructure failure, task failure, invalid patch, budget exhaustion, and resolved statuses separately. No automatic retries. Any authorized retry is a new linked record; keep the original. Main denominators and the handling of infrastructure failures must be fixed before collection.

## Sequence and stopping conditions

1. Prepare and verify task artifacts and review records.
2. Execute a separately authorized repository pilot; retain all records.
3. Review measured costs and precision, select sample counts without consulting task performance, and establish a usage ceiling.
4. Freeze protocol, task membership, environments, configurations, review judgments, and analysis with a new manifest. Never refresh an old manifest to hide amendments.
5. Run source tasks, derive M1/M2/M3 and save immutable decision records.
6. Run target tasks only after locking source verdicts; report the paired case results and uncertainty.

Stop before freeze if eligibility, target overlap, audit evidence, identity, isolation, limits, budget, or sample selection remains unresolved. No paid runs, PDF rendering, or human recruitment is part of preparation.
