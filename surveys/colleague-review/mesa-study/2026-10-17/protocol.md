# MESA: unified model experiment

## Purpose and scope
This fresh series evaluates MESA as a single 25-question questionnaire using its latest explanations. The three methods are MESA, the complete original EFPA Test Review Model (EFPA-TRM), and general benchmark-review instructions. Earlier studies are archived unchanged and not pooled with this series. No human participation, human ease-of-use benefit, or improved decision quality is inferred.

## Fixed design
Requested model gpt-6.1-sol, medium reasoning effort. Four instruction groups: no assigned identity, newcomer, research assistant, benchmark reviewer; five separate conversations per group and method in each of three batches. Total: 180 planned conversations. The 60 real conversations each review ARC-AGI-2 then DesignQA (120 planned benchmark reviews). MESA supplies 40 questionnaires and 1,000 choices if all real responses are valid. The 60 eight-case conversations each classify 17 claims; the 60 sixteen-case conversations each classify 32 claims: 1,020 and 1,920 planned repeated claim answers. These are repeated answers to 49 distinct claims in 24 constructed cases, not independent observations. Both case sets and their expected answers were created before this rerun and have already been used in prior studies; they are not new held-out tests. The same assistant prepared the questionnaire, cases, expectations and analysis.

## Materials and fairness
Each method receives identical benchmark passages, intended uses, case sets, role instructions and common output requirements. MESA alone receives its own definitions, explanations and HLE example; EFPA-TRM receives the complete 90-page extracted document including forms and guidance. Different amounts of guidance and method-specific tasks limit causal comparisons. All MESA conversations receive the identical instrument text, byte-copied from the latest material. Question texts, five choices, IDs and domains remain unchanged. The live survey remains unchanged. This experiment tests text instructions, not use of an interface. Common JSON instructions explicitly require string reviews and string conclusion lists for every method. This clarification is frozen before execution; it differs from earlier study prompts, so results are not pooled. EFPA-TRM is not the answer key. Questions requiring reinterpretation or lacking an AI counterpart must be reported.

## Outcomes and analysis fixed before execution
Eligibility requires completed process and turn, valid JSON with unique keys and the exact task schema, all required questions/cases/claims exactly once, and no observed reviewer tools. No automatic repair or replacement of completed invalid outputs. MESA comments are optional, absent/empty/null allowed; a supplied nonempty comment must be text. Report every exclusion and denominator by batch, method and instruction group. Per-conversation and per-family case matches and changed/unchanged paired answers are descriptive; no significance tests or independent-claim inference. Also count unjustified Supported answers to predefined negative claims for the sixteen-case set. Report five-choice distributions and repeated-choice agreement separately from correctness; never average choices into quality scores. Report variation across all roles and within each role using actual valid denominators.

The six illustrative reviews are fixed as neutral repetition 1 for each method, each covering both benchmarks. Read each entire output against the copied twelve-point checklist. Include selected invalid responses only in a separately labeled qualitative examination; do not replace them. Record exact quotations, information identified or left unaddressed, conclusions needing qualification, and EFPA reinterpretations. These interpretations are by the same assistant and are not an independent correctness key or a population omission rate. Inspect all usable MESA real closing notes for reported ambiguity, retaining exact text rather than treating comments as causal explanations.

## Isolation and execution
Fresh ephemeral Codex CLI conversations with empty work directories, project documents and memories disabled, web search, shell and multi-agent features disabled, read-only sandbox. Reviewer prompts contain only assigned materials and instructions, never expected answers, organizer notes or other responses. Save the exact command and available model settings, timestamps, prompt/material fingerprints, JSONL events, stderr, raw response and failures. Pretrained knowledge and platform instructions cannot be excluded. Backend model revision, temperature and generation seed are unavailable. A scheduling seed changes launch order only. At most three concurrent reviewers; stop scheduling on infrastructure failure. Permit one retained retry only for an execution failure without any completed response or turn. Preserve original attempt and retry. Do not retry a completed invalid response.

## Preservation and reporting
Freeze all inputs, source fingerprints, expected keys, protocol, runner and analysis before testing. No outputs from previous studies enter this series. Current manuscripts and repository descriptions may be updated only after observed results are available; retain earlier records unchanged. The paper calls the questionnaire MESA, without earlier/later instrument variants. Retain an archive note and links in study records for traceability. No LaTeX compilation or PDF preview. Layout and page length remain unchecked.
