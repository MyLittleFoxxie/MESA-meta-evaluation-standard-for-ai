# Analysis rules for author review

29 October 2026. Draft before responses. No results are available. Approaching a review means understanding what a question asks, finding information that bears on it, explaining an answer and recognising uncertainty. Model performance tests parts of this process; it does not measure human approachability.

## Units and counts

Report each model separately. Each model has six fictional sessions, containing 24 cases each, and nine benchmark sessions, containing 50 questions each. Across both models this is 30 sessions and 1,188 planned answers: 288 fictional and 900 benchmark answers. These are planned opportunities, not independent participants or completed observations. Condition B is shared between Studies 1 and 2 and must not be counted twice.

## Reference choices

Before execution, the author checks each reference and assigns assessable, contested or unresolved status. An assessable item has one supported choice. A contested item has documented competing interpretations; list its proposed choice and alternatives without counting it in the main exact match result. An unresolved item lacks a settled reference. Report the counts in all three groups for each reading condition. Freeze these decisions before seeing model responses.

For each session report exact matches divided by assessable items with valid answers, alongside the count of assessable items without a valid answer. Also report exact matches divided by all assessable items assigned to that session, so missing answers cannot improve the headline result. Preserve invalid outputs and follow the protocol's retry rules. Show counts before percentages. Report contested items separately, including whether the response chose a documented alternative; do not quietly broaden the main key after collection.

## Explanations and source use

For every valid response record whether the quoted text or passage identifier can be located in the supplied material. This mechanical check does not establish that the text supports the answer. Separately, the analyst reads the reason and records whether it explains the chosen answer, exceeds the supplied information, or remains unclear. Record the passage and an explanation for each classification. These interpretations require author review; they are not an independent second coding exercise or a measure of coder agreement.

Record specific mistakes separately: treating missing information as a negative finding, treating a reported check as proof of a favourable outcome, confusing repeated setups with changed setups, or answering whether a benchmark is good when the question asks whether something is documented. Categories may overlap and must not be summed as a total error score. Retain cases that do not fit these categories.

## Study 1: question explanations

Present fictional cases separately from benchmark questions. For the fictional cases, also show the six intended distinctions. Three repetitions describe variation within this design; do not infer a population effect or treat each response as a separate person.

## Study 2: summaries

Compare B and C by question and benchmark. Use a table containing the original passage reference, summary reference, choices across the three runs, and the source audit finding. Separate omitted information, changed wording, factual discrepancies and differences with no identified material explanation. A difference caused by a packet error is not automatically a reviewer error. If corrected study material is adopted, preserve the earlier version and freeze new references before execution.

## Presentation and limits

Use one study flow diagram, a count table for Study 1, and a source-to-summary comparison table for Study 2. Select illustrative cases using declared categories, not only favourable results; show all item results in supporting files. Record any later analysis change with its date and whether outputs were already visible. Do not claim human understanding, shorter completion time, or usefulness from these model sessions.
